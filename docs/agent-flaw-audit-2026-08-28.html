2 · Agent flaws — the report

Ten findings, numbered because the spec references them. Weight is the share of the 46 un-proved cases the flaw touched, adjusted up for the flaws that produce wrong-but-confident verdicts rather than mere dead-ends — those are the ones that make a run untrustworthy rather than just incomplete.

F3
weight 10/10

The actual output is read wrong, then trusted

The highest-weighted flaw, and the one your human review caught. Three shapes, all producing confident verdicts from evidence that was never observed:

  • Inference presented as observation. PL_05_16's agent: "shows 1–75 of 75, meaning 100 was selected". PL_04_13's agent: "opened and picked, as confirmed by the successful clicks". An ok click is not a state change; a readout is not a selection.
  • Examples read as facts. "1-15 of 43" in the sheet's Expected column is an illustration; the author asserted count = 43 against a table of 75 (PL_05_12/15). "BP-DENTAL-01" is mock data; asserted as a real row (PL_05_01/04).
  • The judge rules on the words, not the state. PL_04_08: "still visible contradicts hidden" at 0.9 confidence, on a button the human passed by hand — the judge never asked whether "not shown" meant hidden, disabled, or inert.

Twenty of twenty-two agent legs on passed cases were settled by the agent's own "finish" claim (settledBy empty), not by evidence. That is the structural gap: the "what the agent claims is never the evidence" rule is enforced for failures and skipped for successes.

F2
weight 9/10

Roles invented instead of read: combobox, textbox, select

Sixteen dead-ends on one page. The live tree exposes button "Type:", button "Rows per page", searchbox "Search benefit name"; the author wrote role=combobox, role=textbox, native select — the roles a filter usually has, not the ones this page has. ungroundedCountRole already refuses an invented role for expectCount; nothing refuses it for a selector on any other action.

F7
weight 8/10

Test data treated as facts about the application

"Mock Country (TH)", "PL_07_01_02_03_04_05_06", "BP-DENTAL-01", "TH_MED_005", "43 rows": every one is fixture text a human tester was expected to create or read, and every one was asserted as already true. The DB has none of them. Thirteen cases. The agent then spends its whole budget hunting rows that were never seeded — and correctly reports they don't exist, which the run files as a failure against the app.

F1
weight 7/10

The sheet's wording asserted, the page's rendering ignored

"Benefit Plans" vs "Benefit Plan Catalog"; "Plan ID filter" (TBC on the sheet); role=dialog for a pop-up the Note says became a page. The lint added this week (ungroundedTextExpectation) catches the text form; the structural form — a dialog scope, a filter that was cancelled — is not caught.

F5
weight 6/10

Disabled controls treated as usable

The search box is disabled at rest and the repo's own test says search "starts disabled until a filter is chosen". Six flows fill it first. The tree carries the disabled token on the line; nothing reads it.

F4
weight 5/10

The agent proves state by re-doing the action

PL_03_07 and PL_05_16 stalled on "repeated click after being told it was done": the agent could not tell whether Country/Rows-per-page had taken, so it clicked again. It has no cheap way to read a control's current value, so it acts to find out.

F6
weight 4/10

A content mismatch dead-ends instead of reaching the judge

PL_02_07's breadcrumb text mismatch was stamped dead-end. The near-miss gate (proved-? → judge → human) exists for exactly this and was never reached. Partly fixed today (the contentOnly rule); this run predates it.

F8
weight 4/10

The risk judge is right and nobody listens

Pre-run risk said "fail-fast 0.78 — the search box starts disabled" on PL_03_08/10/13, "0.86 — needs a dropdown the page doesn't have" on PL_04_03, "0.88 — needs a Start date filter that doesn't exist" on PL_04_09. Every one then ran its full ladder. The judge's evidence was never fed back into authoring; it only shortened retries.

Nine cases errored with "needs the multi-page agent, but none is configured". A resume that drops a role the original pass had should refuse at the boundary, not per step.

3 · Optimization spec

Eight changes, ordered by weight covered. Each is a guarantee in code, never a prompt request — the same principle every rail in this codebase follows. Together they cover all ten findings; F6 and part of F1 are already shipped today and are listed for completeness.

S1 · Observed-state settlement for agent success covers F3 · F4

The rule "what the agent claims is never the evidence" is enforced only on failure. Extend it to success: a finish is accepted only when the goal's claimed end state is re-read from the live tree by the harness, not asserted by the model.

  • Add goalOutcome() in goal-evidence.ts: from the goal text, extract the checkable end-state (a control's value — "Rows per page = 25"; a filter label — "Status = Inactive"; a count — "1–25 of N"; a surface — dialog/page title). Mirror of goalSurfaceNames, extended to values.
  • On finish, the loop captures the tree and evaluates the outcome deterministically. Hit → settledBy: 'observed-state', evidence = the node text. Miss → the finish is refused once with the observed value quoted ("the tree shows Rows per page = 15, not 25"); second insistence records success: false, summary "claimed finish, but the page shows …".
  • Goals with no extractable outcome fall back to today's behaviour, but the record says settledBy: 'agent-claim' explicitly and the roll-up counts them — so an all-claim run is visible as such.
  • Agent vocabulary: add a read action (selector → the harness returns the node's name/value/checked/expanded into history). Gives the agent a $0 way to know a control's state instead of re-clicking it (F4).

S2 · The judge compares states, and cites which covers F3

The near-miss judge rules "expected vs actual" as two strings. Make it a three-way comparison: expected wording, observed state (visible / hidden / disabled / enabled / value — the ladder already records these as detail.actual), and the human-recorded Actual Result when the sheet has one. The verdict must name which state it believes satisfies the claim; a ruling of "failed" against a human "Passed" is auto-downgraded to needs-review — the judge may not overrule a human record without a person.

S3 · Fixture facts are not application facts covers F7 · F3

Every identifier and value that comes from the sheet's Test Data / Expected columns is tagged at authoring as fixture. A fixture value may be typed (fill, select) but never asserted to pre-exist (a where-clause, a row click, a count) unless the run has seen it created — by an earlier step of the same flow, or by a chained case the ledger recorded as passed.

  • fixtureFacts(row) extracts ids/values; ungroundedFixtureAssertion(steps, facts, dbSchema) refuses an expectDbRow/click row X/expectCount N on an untyped fixture with: "PL_07_01_02_03_04_05_06 is test data this case must create or a prior case must have seeded; nothing in this flow creates it".
  • An example readout in Expected ("1-15 of 43") is classified illustration, never a number to assert; the author asserts the shape ("N–M of Z" with Z read from the page) instead.
  • Chained preconditions (PL_03_09 needs PL_03_07's row) become an explicit requires: [caseId] on the flow; the suite blocks the dependent as "precondition never seeded" instead of running it into a false failure.

S4 · Roles are read from the tree, for every action covers F2 · F5

Generalise ungroundedCountRole to every selector on every action: a role=X[name=Y] is accepted only when some tree line starts with role X and carries name Y (case-folded); otherwise the lint names the real line ("the tree has button "Type:", not a combobox"). Same for select/[role="…"] CSS spellings. And read the state tokens the tree already prints: a fill/click on a node marked disabled is refused with "this control is disabled at rest — the repo's test says a filter must be chosen first".

S5 · Vacuous-pass detection on the page, not only on the flow covers the two hidden bugs

vacuousFlow checks a flow's assertions in the abstract. Add a runtime check: an expectVisible whose selector resolves to an element with no accessible name, or a positional >> nth=N on a role the tree does not have, passes with vacuous: true on the step and the case is scored needs-review, never green (PL_04_13). And a claim whose sheet Expected names a value (a date, an amount) may not be satisfied by a presence assertion alone — wordingClaimAssertsDataValue already exists for wording; extend it to values (PL_07_06).

S6 · The risk judge's evidence feeds the author covers F8

When the pre-run risk verdict is fail-fast with a concrete reason ("search starts disabled", "no Start-date filter exists"), the reason is sent back as authoring feedback for one re-ask before the run — the healer's rejected seam, applied one stage earlier. The judge already knows the answer; today it only shortens the funeral.

S7 · The Note column is a gate covers F10 · F1

Rows whose Actual/Note say Cancelled, TBC, or carry a dated requirement change ("pop-up → page 4 Aug") are handled before authoring: Cancelled → blocked "cancelled on the sheet", never a model call; TBC → authored as needs-review from the start; a change note is prepended to the case card so the author reads "this is now a page, not a dialog" before it writes role=dialog.

S8 · A resume refuses a missing role at the boundary covers F9

The ledger records which roles the original pass had. A resume whose config lacks one refuses to start with the role named and the two fixes (configure it, or --no-agent explicitly to accept the downgrade). Nine per-step errors become one honest line.

Expected effect, from this run's own numbers. S3 + S4 + S7 remove 30 of the 34 false positives at authoring time (they never reach the browser). S1 + S2 convert the confident-but-wrong verdicts (PL_04_08, PL_05_16, PL_04_13) into observed states or explicit reviews. S5 catches the two hidden real bugs. What remains is what a run should spend its budget on: PL_06_05/06 — the two defects the human also found.
