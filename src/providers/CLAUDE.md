## Structured output on free tiers

`generateStructured()` in `src/providers/llm-factory.ts` is the one place `generateObject` is called. **Every call runs at `temperature: 0`** — nothing here is creative writing, and sampling around the most-likely answer is where run-to-run inconsistency came from (the same claim authored as 25 steps one run and 29 the next, with different invented roles). Two more rules follow from running on free models:

- **Keep generated schemas flat.** `GeneratedStepSchema` and `DecisionSchema` are flat objects with every field required and empty strings for unused fields, then narrowed in code (`toFlowStep`). Weaker models handle that far more reliably than a five-variant `discriminatedUnion`. The zod discriminated union in `src/mcp/server.ts` is fine — that one is an MCP *input* schema, not a model *output* schema.
- **Never trust a number.** Smaller models return confidence as `0–100`, `1.4`, or a string. The healer clamps to `0–1` in code; the schema is not the guard.
- **Every property of a generated schema must appear in its `required`.** Strict structured-output providers — Groq's `openai/gpt-oss-*`, OpenAI's own — reject an object schema whose `required` omits any key of `properties`, and they reject it *before the model is asked*, so the whole call fails with a schema-validation error rather than a bad generation. `.optional()` and `.default()` both produce exactly that shape, which makes them unusable in a model-*output* schema however reasonable they look. An optional field is spelled `.nullable()` instead: the key stays in `required`, and `null` is how the model declines it. When the field must *also* survive a lenient provider omitting it, wrap the object in `z.preprocess` and fill the key — `AuthoredStepSchema` in `flow-author.ts` is the worked example, and the reason `case` is the only field there not following the flat empty-string convention. Env schemas in `src/config.ts` are exempt: they validate `process.env` and never reach a model.

- **Ask a schema-in-prompt provider for an *instance*, and say so.** A provider with no structured-output channel (`emmiedev`, `zai`, `deepseek`, `local` — `SCHEMA_IN_PROMPT_PROVIDERS`) is told the schema in prose by `promptSchemaInstruction`, and **the wording of that instruction is load-bearing**. "Respond with a JSON object that matches this JSON schema exactly" is ambiguous, and GLM 4.7 reads it the wrong way: it replies with *the schema*, its answers tucked into `const` fields. That is valid JSON, so `json_object` mode is satisfied and nothing catches it until zod rejects every field as `undefined` — surfacing as "No object generated: response did not match schema", which reads like a model that cannot do structured output at all. It can; it answered the wrong question. Two things provoke it: **nesting** (the failure tracks schema shape, not model quality — measured on glm-4.7-flash, the healer's flat four-key object came back correct 4/4 while the generator's `steps: array of objects` managed 3/8) and **`$schema`**, which `z.toJSONSchema` emits and which reads as a document worth echoing. So the key is dropped and the instruction names the distinction outright, listing the keywords a schema echo would contain rather than hoping against it. Same prompts, same model: **8/8**. `echoedTheSchema()` also names this failure in the error when it does happen, because "response did not match schema" is otherwise opaque.

**A model that cannot do schema output is a SYSTEM failure, and it stops being paid.** Exhausting the re-ask budget throws typed `StructuredOutputUnavailableError`; the exit contract maps it to `EXIT.environment` (fix the role's routing, never file a bug against the app). Two exhausted cycles in one process trip a **circuit breaker** (`BREAKER_TRIPS`): every further call to that model fails immediately with "circuit is open" instead of spending three calls and their timeouts to relearn the same fact — seen live with `openrouter:google/gemini-3.6-flash` on the healer role, which burned a re-ask cycle per failing step. A success halves the count rather than clearing it, so one good roll from a mostly-broken model does not reset the evidence. `resetStructuredBreaker()` is the test seam.

Not every free model can emit schema-constrained JSON at all. When one can't, `generateStructured` throws with the model label in the message — that's deliberate, because the useful question is *which* role broke, not that JSON parsing failed. **The advice attached to that message is chosen by cause, not boilerplated:** a key failure (rate limit, quota, expired credential — `isKeyExhaustedError`) says so, because "try a different model id" would send someone editing config over a call that was rate-limited and whose model was fine. Note z.ai signals overload as error code `1305` and the SDK does surface it as a rate limit, so key rotation already works.

### Thinking models behind OpenRouter, and a response cut at the budget

`openrouter:google/gemini-3.6-flash` — every role's default in this checkout — thinks before it answers, and the thinking bills against `maxOutputTokens`. `REASONING_OUTPUT_FLOOR` already covered that fact for the `google` provider by raising the budget; it did not cover `openrouter:google/…`, and the whole of "returned an unusable object (No object generated: could not parse the response)" was this. Measured, one authoring-sized call four ways: 2048/default → `finish=length`, 241 chars of JSON; 8192/default → `finish=length` after 38s, ~7.3k hidden; `reasoning.effort: none` → refused ("Reasoning is mandatory for this endpoint"); `reasoning.max_tokens: 256` → `finish=stop` in 3.6s. So `withReasoningCap` sends `reasoning: { max_tokens: OPENROUTER_REASONING_MAX_TOKENS }` for the model families that think by default (`OPENROUTER_REASONING_MODEL`, gated on the model id — OpenRouter fronts hundreds of models and a `reasoning` field sent to one that has none is at best ignored) and adds the cap back onto the visible budget.

**The cap is soft.** Gemini treats a thinking budget as a target; a hard prompt was still measured spending ~8.9k reasoning tokens against the 1024 cap. So the second half is structural: **a response cut at `finish=length` is re-asked with double the budget** (`wasCutAtBudget`, `MAX_STRUCTURED_OUTPUT_TOKENS` 32k), never the same one — at `temperature: 0` an identical request is answered identically, and before this the re-ask loop repeated a length cut three times, tripped the breaker, and put a whole catalog run down. `LlmFlowAuthorModel` starts at 16k for the same reason: every authoring call of any size was cut at 8k and rescued at 16k, one call later. The failure text names it: "the JSON was CUT OFF at the output budget … cap the reasoning or raise maxOutputTokens". Gemini reached through the `google` provider gets the same cap on its own dial (`thinkingConfig.thinkingBudget`, measured 20.6s/1,727 thinking tokens → 10.9s/303; `0` is rejected as invalid — thinking is mandatory on this model). Neither cap changes what a model answers at `temperature: 0`; both change how long it takes and how often the answer arrives whole.

### A model on this machine (`local`, the `rerise` server)

`local` is mlx_lm.server behind `~/.local/bin/rerise` (its wrapper `~/mlx-env/bin/rerise_server.py`), and three facts about it are load-bearing, all measured 2026-08-21:

- **There is no model to choose.** The server answers with the `--model` it was started with; mlx_lm's alias for it is `default_model`, and any other id — `default` included — is treated as a Hugging Face repo to fetch. `FIXED_MODEL_ALIAS` / `FIXED_MODEL_PROVIDERS` in `config.ts` make the role resolve to the alias whatever `WOWLIDATOR_<ROLE>_MODEL` says, and the panel shows no model field for it.
- **It answers one call at a time.** Prefill is serialised (`--prompt-concurrency 1`), decode batches two. Three concurrent calls measured 5.7 / 6.2 / 9.4 s against 4.0 s alone; three authoring prompts in flight put the third behind two full prefills, and one of the three returned garbage. `SERIAL_PROVIDERS` / `authorWorkers()` in `case-plan.ts` therefore author rows one at a time when the generator role is on `local` unless `--author-concurrency` says otherwise; `--concurrency` for *runs* is untouched (a run is browser-bound).
- **The schema travels in the request, and the server shapes the reply to it.** mlx_lm ignores `response_format`; the `rerise` wrapper does not. The `local` factory entry sets `supportsStructuredOutputs: true`, so the SDK sends `response_format: { type: 'json_schema', json_schema: { schema } }` (the schema is *also* stated in the prompt — `withPromptSchema` — because the model still has to be asked). On the server, a non-streaming reply to such a request is repaired (fence stripped, `<think>` dropped, the object pulled out of surrounding prose) and then **coerced to the schema**: every required key present with its type's empty value, lossless scalar casts, a lone object wrapped where an array was asked for, one level of `{"result": …}` unwrapped. Nothing is invented — an enum the model left out stays out, and zod still has the last word. A reply that could not be made into JSON is kept whole under `~/.cache/rerise/bad-json/` so the defect can be read instead of guessed from the client's first 160 characters.

**Google is paced, not retried into** (`src/providers/rate-pacer.ts`). AI Studio meters RPM/TPM/RPD per model per key and has **no endpoint that states a key's limits** — the only time it names one is a 429 body (`QuotaFailure…quotaValue`, `RetryInfo.retryDelay`). So `RatePacer` starts from the documented free-tier table (`GOOGLE_FREE_TIER_LIMITS`, `WOWLIDATOR_GOOGLE_RPM/TPM/RPD` override), **learns the ceiling a 429 names**, and `reserve()`s before every request at the one real call site (`attemptStructured`, so re-asks count too): under `PACER_HEADROOM` (90%) it sends, otherwise it waits for the oldest sample to leave the minute, logs why, and never waits past `PACER_MAX_WAIT_MS`; a spent day is a typed `RateBudgetExhaustedError`, not a silent wait for midnight. A 429 is waited out for the stated delay and retried **on the same key** (`RATE_LIMIT_RETRIES`) before the failover sees it — rotating keys over a full minute spends the next key on the same minute. Day counts persist in `.wowlidator/llm-usage.json` keyed on `provider:model@…<key tail>`, because a catalog is many CLI processes. The day boundary is UTC, conservative against Google's Pacific reset by up to 7 h — disclosed, not hidden.

**Every model request and response is logged** (`src/providers/llm-log.ts`): `→ role · task · model · request #N · ~tokens · pacing` with the first line of the ask, `← … · Ns · in/out · session totals` with the returned object (cut at `WOWLIDATOR_LLM_LOG_CHARS`; `WOWLIDATOR_LLM_LOG=full` for all of it, `off` for none), `✗` for a failure with the retry delay. **stderr only** — `--json` owns stdout and so does MCP. Keys never reach it: the model label is `provider:modelId`, URLs are stripped from error text, the pacer id carries four characters of the key. `StructuredRequest.task` is how a caller names what it is asking for beyond the role.

**One server, four roles: admission is decided here, not in the server** (`src/providers/serial-gate.ts`). A `SERIAL_PROVIDERS` role's structured calls enter a per-server gate (keyed on the role's base URL, so two ports are two resources): at most `SERIAL_MAX_IN_FLIGHT` (2, the server's decode batch) in flight and at most one *large* prompt (≥ `SERIAL_LARGE_PROMPT_CHARS`, the authoring/repair shape whose prefill blocks everyone); waiters are served `agent` → `healer` → `data` → `generator` (who is blocked on the answer, not who asked first), FIFO within a role so authoring keeps sheet order; and an identical in-flight question (same role, model, system, prompt — never one carrying images) is asked once, the joiner charged no tokens. It changes *when* answers arrive, never *what* they are — temperature is 0 — and a non-serial provider is untouched. `--author-concurrency 1` on local stays the default; the gate is what makes the healer/agent calls of four parallel *runs* safe beside it. **A role's server is per role**: `WOWLIDATOR_<ROLE>_BASE_URL` (the panel's port field next to a `local` role) overrides `LOCAL_LLM_BASE_URL`, so a small model on a second port can take the latency-sensitive roles while the 9B authors.

**The local transport waits, and never re-sends** (`src/providers/local-fetch.ts`). Node's global fetch gives up waiting for response headers at 300 s, and a non-streaming completion sends none until the generation is done — so a 20k-token prompt that takes four minutes had the client hang up, the SDK retry at once, and the retry queue behind the generation the server was still finishing for nobody (its log now says "client disconnected before the response was sent"). `local` uses its own undici `Agent` with `LOCAL_LLM_TIMEOUT_MS` (default 15 min) on headers and body, and `withPromptSchema` sets `maxRetries: 0` for it — a reply that has not arrived is a different thing from a reply that arrived unusable, which the re-ask loop still handles. Both are `local`-only.

**A re-ask after a malformed reply carries the complaint** (`reaskNote`, any provider): at `temperature: 0` an identical request gets the identical malformed reply — seen as "could not parse the response" ×3, finish=stop, then the breaker — so the second ask appends what was wrong (the zod issues, or "not valid JSON" with the usual causes) and the instruction to answer with one valid object. The length-cut re-ask already changed the budget for the same reason; this is the same rule for the other failure.

## Prompt discipline (`src/providers/prompt-discipline.ts`)

`temperature: 0` removed the sampling half of run-to-run variance. The other half was never sampling: nine prompts of true rules with no order to apply them in, no rule for what to do when two pull apart, and no moment at which the model checks its answer. Three shared blocks, so the discipline is one thing across nine prompts: `DETERMINISM_RULES` (same evidence, same answer; ties break shorter-then-earlier-in-the-evidence; never an optional step; values verbatim), `procedure()` (a numbered order of decisions — given the same evidence, a model that follows the same steps arrives at the same answer), and `selfCheck()` (a checklist run before answering, worded "fix the answer, never explain the miss"). Zero-shot on purpose: an example teaches the surface of one answer and is copied where it does not fit; a procedure teaches how any answer is built. `SELECTOR_SYNTAX_RULES` gained a **canonical form** — one way to write each thing, including the nameless password textbox (`input[type="password"]`) — so the same tree yields the same selector; measured after: 3/3 identical agent decisions, 2/2 identical heals.

The author prompt's procedure names the case by the request's own id **verbatim** (PB_01_01), knows the **two-step sign-in** (identity → Next → `input[type="password"]` → submit — the password field is not in the login tree because it does not exist yet, and that is not a reason for a workflow step), and settles a **consent gate** with the authored `clickIfVisible` (narrows to the engine's `when { visible } then [click]`, whose probe never heals — one step rather than a `workflow` leg per run or a `click` that fails setup on every run after the first). Credentials have an explicit precedence: the request's own persona lines, then `SIGN IN AS`, then a placeholder with a note — a single `--as` must not overwrite a three-persona catalog. The one lint that fired on nearly every row of every measured run — a login proved by `expectUrl "/en/"`, which the sign-in URL already contains — is now **repaired mechanically before it can refuse** (`groundLoginProof`: the vacuous check becomes `expectHidden` of the very submit control the flow clicked, disclosed on `notes`), the `groundCredentialFills` move again: a string replacement should never cost an authoring call. Two more of the same move, both from glm-4.5-flash's habits: a selector written in the TREE'S own notation is rewritten to real syntax (`fromTreeNotation` — `StaticText[text="…"]` → `text="…"`; `role=cell[text="…"]` → `[name=]`, since a cell's accessible name is its text; `role=link[url*="…"]` → `a[href*="…"]`, since the tree prints `url=` on links and the role engine has no such attribute; all three shapes live in one catalog run), and an `expectHidden` on an UNQUOTED bare word (`text=extended`, a substring match that fires on the page's legitimate "Extended" label) is quoted to the exact form; snake_case tokens stay as written. The prompt states the canonical login proof outright now — `expectHidden` of the submit control just clicked, the same for every persona; `expectUrl` only for a path the evidence states (`SIGN-IN LANDING`, a `url=`) — because a guessed landing (`/en/employees` for a persona that lands on `/en/admin/employees`) failed four cases identically, 10 slow seconds each. `notEndToEnd` counts a click on a `role=link` as travel, since a flow whose login proof is no longer an `expectUrl` can honestly navigate with no URL claim at all. And `DEFAULT_PROVIDER_MODELS` in config: a role's provider re-pointed WITHOUT a model no longer inherits a model id belonging to a different provider (`WOWLIDATOR_GENERATOR_PROVIDER=zai` alone used to resolve `zai:gemini-3.6-flash`). Every workflow goal covers one leg, names its concrete values, and **ends with its destination path**. `signInOnCaptureTab` learned the same two screens and the same gate, because "no visible password field" was true of every login page and the journey capture had been giving up silently on every case.
